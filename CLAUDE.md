# CLAUDE.md

Operating manifest for this repo. Loaded in every session.

## Mandatory state

The product is a **local-first** personal finance app for iOS. GRDB on device is the source of truth for reads and writes; the app is fully usable with no account and no network. Supabase exists for one thing, the opt-in **snapshot backup** (ADR 009): no row replication, no multi-device convergence. A sync engine is not coming back; the schema keeps the columns a future one would need (ADR 009 Decision 9).

This repo is a rebuild of the JustChill Android app for modern iOS (ADR 018): same product, same domain, same way of working, nothing ported line by line. Today only `CoreDomain` and `CoreUI` exist as scaffolds; every other package below is the target shape and is created by the ticket that first needs it.

No third-party users, but the owner runs the app daily and its data is real. UI is cheap to redo; a destructive migration is not. The owner's `iPhone 17` simulator on iOS 27.0 holds dev data: never seed it, never erase it, never recreate it.

## Packages

```
App             -> Feature*, CoreBackup, CoreDatabase, CoreUI, CoreDomain
Feature*        -> CoreUI, CoreDomain (+ CoreTesting on the test target)
CoreBackup      -> CoreDomain
CoreDatabase    -> CoreDomain
CoreUI          -> CoreDomain
CoreTesting     -> CoreDomain
```

- `App/` — the composition root, an Xcode app target generated by XcodeGen from `project.yml` (ADR 019): `JustChillApp`, `AppContainer` (manual DI, one `make<Screen>Model()` factory per screen) in `App/Composition/`, `RootView` with the `NavigationStack` and the `Route` enum in `App/Root/`. The only code that names an implementation type.
- `Packages/CoreDomain` — **pure Swift**, Foundation only: entities, value objects, use cases, repository protocols, the `DomainError` enum, the injected `Clock` and `TimeZone`. Builds for macOS too, so `swift test` runs it on the host.
- `Packages/CoreDatabase` — GRDB.swift: the `DatabaseMigrator`, records, the repository implementations and the snapshot store over the six tables.
- `Packages/CoreBackup` — supabase-swift: the snapshot file, its format versions, Storage, the backup cycle and auth. Never depends on `CoreDatabase`; a snapshot crosses as domain values.
- `Packages/CoreUI` — the UI vocabulary more than one feature uses: tokens (`Theme/`), atoms (`Atoms/`), the Spanish money and date formatters, shared sheets and pickers, and route payloads more than one feature references. Never depends on `CoreDatabase` or `CoreBackup`.
- `Packages/CoreTesting` — fixtures and fakes on `CoreDomain` only, wired into feature test targets.
- `Packages/Feature<Name>` — one screen family each: account, auth, category, loan, onboarding, profile, recurring, report, transaction. Its `@Observable` models, its screens and their `Content` views, its route payloads, its tests. Features never import each other.

SwiftPM enforces the graph: a target imports only what its `Package.swift` declares. `project.yml` is the only place the app target and the scheme are written; `justchill.xcodeproj` is generated and gitignored. A remote dependency's version is written once, in the `Package.swift` that uses it.

## Product

Manual capture of income and spending in soles, in under fifteen seconds per movement; accounts, categories, recurring movements, a month report, and informal loans as a parallel ledger. Spanish only, free, no ads, no bank sync. The Won't-have rows and the acceptance criterion: `docs/PRODUCT_REQUIREMENTS.md`. The vocabulary: `CONTEXT.md`.

## Non-negotiable rules

These bind on every change, including a new file created before any Swift has been read.

- **No comments.** No `///`, no `//`, no `/* */`, no `// MARK:`, no commented-out code. The code explains itself or it gets renamed. Three narrow exceptions in `.claude/rules/swift-style.md`.
- **Explicit types** on every stored property and every local `let` / `var`, and the protocol when the abstraction is what matters. Omit only when the right-hand side is a constructor call that already names the type.
- **Only CoreUI atoms in feature views.** Never a raw styled SwiftUI control. See `.claude/rules/ui-components.md`.
- **One `@Observable` model per screen**: a `final class <Screen>Model` in its feature package. State is stored properties, user actions are methods, one-shot outcomes are state the view reacts to. No `ObservableObject`, no Combine, no Intent or Effect enums, no base class. A model never imports SwiftUI; `scripts/check-swiftui-free-models` is on the gate.
- **`CoreDomain` stays pure Swift.** Foundation only. If it needs to reach outward, invert with a protocol in `CoreDomain`. A failure mode is a new `DomainError` case, never a new error type.
- **Dates take an injected `Clock` and `TimeZone`, no defaults.**
- **Rebuild, never adapt.** When existing code, config or structure does not fit the target architecture, replace it with a clean implementation. No shims, wrappers or compatibility patches over legacy. This binds the port from Android too: port the philosophy and the domain, never a Kotlin idiom.
- **`scripts/gate` green** before every commit. The script is the gate's definition; never a prose copy.
- **Every pushable destination is a `Route` case** handled by `RootView`'s exhaustive `switch`. The path is `[Route]`, never `NavigationPath`, so an unhandled or foreign value does not compile.
- **A schema change appends one new named migration** to the `DatabaseMigrator`, never edits a shipped one, and ships a migration test from a fixture database per prior version plus the restore drill. See `.claude/rules/grdb.md`.
- **English for every identifier; Spanish only in user-facing values**, addressing the reader as tú, never vos.
- **Never add `Co-Authored-By`** from Claude, Anthropic or any AI assistant to a commit message; a hook blocks it. Conventional commits, linear history. Never push `trunk` without being asked, with one exception: the orchestrator pushes the docs-only commits that close a wave (the dispatch log) on its own.

## Stack

Xcode 27, Swift 6.4 with strict concurrency and approachable concurrency, iOS 27.0, SwiftUI only, Observation, GRDB.swift, supabase-swift, Swift Testing, XcodeGen. No analytics, no third-party UI kit.

## Commands

- `scripts/gate` — the gate CI runs: `scripts/check-swiftui-free-models`, then XcodeGen when stale and `xcodebuild build test` on `iPhone 17` iOS 27.0. `JUSTCHILL_SIMULATOR=<udid> scripts/gate` runs it on another simulator; a peer always sets it.
- `scripts/build [action ...]` — XcodeGen when stale, then `xcodebuild` with the given actions, `build` by default. Build only; not a gate.
- `scripts/check-swiftui-free-models` — fails on any `import SwiftUI` in a `Packages/Feature*/Sources/**/*Model.swift`.
- `swift test --package-path Packages/CoreDomain` — the domain's tests on the Mac host in seconds. A fast loop, never a gate substitute.
- `xcodegen generate` — regenerate after editing `project.yml`; `scripts/build` already does it when the spec or the file tree moved.
- A package's tests run on the gate only once its test target is listed under `schemes.justchill.test.targets` in `project.yml`. A test target missing there is green by absence.

## Test stack

Swift Testing: `@Test("sentence naming the rule")`, `#expect`, `#require`. No XCTest for unit tests; XCUITest is reserved for one smoke test (launch, capture one movement), added later. Fixture locals are named by role. A model under test gets `CoreTesting`'s fakes and a fixed `Clock` and `TimeZone`. A test that waits observes the transition, never samples the state: subscribe before triggering and assert the recorded sequence. A getter whose deletion leaves the suite green is not covered.

## Custom slash commands

- `/checks` — `scripts/gate`, failures grouped by package.
- `/feature <Name>` — full scaffold for a new `Packages/Feature<Name>` package, wired into `project.yml` and `AppContainer`.
- `/agents-review` — review the pending diff against these rules.
- `/release` — tag trunk and publish a GitHub release.
- `/wave <issues>` — boot one peer session per ticket and dispatch.

## Final rule

If a doc contradicts the current code, the code wins and the doc gets updated afterwards.
